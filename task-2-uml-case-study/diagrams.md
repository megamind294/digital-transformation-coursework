# Reconstructed UML-Style Diagrams

These diagrams were newly created for this public portfolio reconstruction; they are not claimed as original submitted coursework diagrams.

## Use-case view

```mermaid
flowchart LR
    Customer((Customer))
    Agent((Service Agent))
    Manager((Team Manager))
    IdP[Identity Provider]
    Notify[Notification Service]

    Submit([Submit request])
    Track([Track request])
    Update([Review / update request])
    Resolve([Resolve request])
    Report([View workload and KPI report])
    Auth([Authenticate])
    Send([Send status notification])

    Customer --> Submit
    Customer --> Track
    Agent --> Update
    Agent --> Resolve
    Manager --> Report
    Submit --> Auth
    Track --> Auth
    Update --> Auth
    Resolve --> Send
    Update --> Send
    Auth --> IdP
    Send --> Notify
```

## Activity view — request lifecycle

```mermaid
flowchart TD
    A([Start]) --> B[Customer enters request]
    B --> C{Required data valid?}
    C -- No --> D[Show validation errors]
    D --> B
    C -- Yes --> E[Create request record]
    E --> F[Route to responsible team]
    F --> G[Notify customer: submitted]
    G --> H[Agent reviews request]
    H --> I{More information needed?}
    I -- Yes --> J[Request additional information]
    J --> H
    I -- No --> K[Perform service work]
    K --> L[Mark resolved]
    L --> M[Notify customer: resolved]
    M --> N([End])
```

## Sequence view

```mermaid
sequenceDiagram
    actor Customer
    participant Portal
    participant Identity as Identity Provider
    participant Workflow as Workflow Service
    participant DB as Request Database
    participant Notify as Notification Service

    Customer->>Portal: Sign in
    Portal->>Identity: Authenticate
    Identity-->>Portal: Authenticated session
    Customer->>Portal: Submit structured request
    Portal->>Workflow: Validate + create request
    Workflow->>DB: Persist request
    DB-->>Workflow: Request ID
    Workflow->>Notify: Send submitted notification
    Notify-->>Customer: Status message
    Workflow-->>Portal: Request created
    Portal-->>Customer: Show request status
```

```mermaid
flowchart LR
    Browser[Customer / Staff Web Client]

```

## Modelling observations

The diagrams separate user interaction, workflow responsibility, persistence, identity, notifications, and analytics. This separation makes it easier to reason about access control, system boundaries, ownership, failure points, and the data generated by the transformed process.
